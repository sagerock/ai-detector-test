# Testing an AI detector: data and code

Everything behind the claims in the accompanying post. Published so the numbers can be
checked rather than taken on faith, which is the whole point of the exercise.

Detector: **Pangram 4**, accessed through its API in August 2026. Model pinned
explicitly to `pangram-4` on every call.

## What's here

| | |
|---|---|
| `corpus/` | 50 court opinion excerpts, 9 Wikipedia excerpts |
| `arms_txt/` | 10 machine-written versions of the post |
| `results/raw/` | Unmodified API response for every document |
| `results.csv` | Summary table, derivable from the raw responses |
| `manifest.csv` | Every document with its ground-truth basis and source URL |
| `code/` | Sampling and scanning scripts |
| `PRE-REGISTRATION.md` | Predictions, written before any document was scanned |

Every document is either publicly verifiable or machine-generated for this test.
Nothing written by a private individual is included.

## Ground truth

This is the part that decides whether any of it means anything.

**Court opinions.** Sampled from the CourtListener bulk export of 2025-12-02. Filed
before 2020-01-01, precedential status Published, judge named, OCR'd documents
excluded. Drawn by reservoir sampling from 5,204,317 eligible clusters, so the sample
is random rather than convenient. The human label rests on a filing date in the public
record.

**Wikipedia.** Last revision before 2018-01-01 for each article, fetched through the
MediaWiki API. Every entry carries its revision ID; the `source_url` column resolves to
the exact text that was scanned. The human label rests on a revision timestamp.

**Post arms.** Written by language models for this test, so the machine label is
certain. One identical prompt for all seven rewrites: *"Please write this so it doesn't
sound like AI wrote it."* First response from each model, no retries, no selection.

Note what is *not* used as ground truth anywhere: anybody's recollection of how they
wrote something. Self-reported labels are the weak link in this entire field, including
in the published false-positive rates that detector companies quote.

## Excerpting

Uniform and mechanical. Court opinions: collapse whitespace, take `words[200:600]`. The
200-word skip clears the caption block, docket numbers, and the clerk's filing stamp,
none of which is judicial prose. Wikipedia: first 400 words of the lead after stripping
templates, references, and markup. Post arms: full essay body with markdown removed,
tables dropped, applied identically to every arm.

## Reproducing

```bash
pip install requests
export PANGRAM_API_KEY=...
python code/pangram_scan.py scan --model pangram-4
```

Roughly $0.05 per 100 words at Developer-tier pricing. The full set here cost about $22.

## Two things worth knowing about the API

The `default` model selector returns **Pangram 3.3.2**, not 4. Confirmed 2026-08-21.
Nothing in the interface tells you which model scored a document, so anything published
should pin the version and record what came back. Every raw response here includes it.

The bulk CSVs in the CourtListener export use Postgres `COPY` escaping. Parsing them
with a default CSV reader silently misaligns columns rather than erroring, which puts
HTML inside boolean fields. Use `escapechar='\\', doublequote=False`.

## Limits

- 50 documents cannot test a claimed 1-in-24,300 false positive rate. That would take
  roughly 24,000. Nothing here attempts it.
- Everything tested sits at one pole or the other: entirely human or entirely machine.
  The middle, where a person writes with varying degrees of help, is untested here and
  is where the vendor's own published numbers are weakest.
- The opinion sample skews recent, 39 of 50 from the 2010s, reflecting digitization
  coverage rather than any selection choice. All 50 predate 2020 regardless.
